Privacy Policy

Effective date: 17 September 2026

This Privacy Policy explains how Zync, the Android app with package name com.gmail.gentle3f.myproject, handles data in the rebuilt Zync V1 experience. Zync is a face-to-face social icebreaker designed around local interest profiles, QR exchange, local matching, and optional AI-assisted conversation features.

1. No account is required

Zync V1 does not require registration or a user account. Zync does not maintain a permanent cloud user profile for the V1 app.

2. Data stored locally on your device

Zync can store the following information locally on your device:

  • an optional nickname;
  • your supported/preferred language;
  • selected interests and their Love / Like / Want to try strength;
  • locally created custom-interest labels and categories; and
  • Zync Again history, such as a local peer identifier or nickname received during a Zync, shared-interest identifiers, timestamps, and repeat-session count.

This local profile and Zync Again history are not cloud-synced by Zync V1. Clearing the app's storage or uninstalling the app normally removes this local data from that device, subject to Android or device-backup behaviour outside Zync's control.

3. QR sharing and the temporary encrypted relay

When you choose to show your Zync QR, the QR contains the information needed for the other device to compare interests locally. This can include a random local Zync profile identifier, your optional nickname, language, selected interests and strengths, labels/categories needed to display custom interests, plus a random short-lived session identifier, expiry time, and a one-time encryption secret for that pairing.

The person who scans your QR receives the QR information visually and locally through the camera. Zync does not upload the host's QR profile body to the relay when the session is created. The scanner performs the initial comparison locally.

To let both phones complete a one-scan Zync automatically, the scanning phone prepares the limited profile information the host needs for the same local comparison and encrypts it on the scanning phone using AES-GCM with the one-time secret from the QR. Only the encrypted response is then sent through the Zync Vercel API to a short-lived Upstash Redis relay. The relay receives a random session identifier, opaque ciphertext, expiry/status information, and limited technical request metadata needed to operate and protect the service. Zync's relay code does not receive the one-time decryption secret and is not designed to decrypt the profile response.

The host phone polls for that encrypted response, decrypts and authenticates it locally, verifies the session and expiry, performs its own local match, and then requests deletion of the relay session. A relay session is designed to expire automatically after about three minutes even if a phone disconnects or abandons the flow. Successful sessions are deleted earlier after the host completes authenticated decryption.

You should only show or scan a Zync QR with someone with whom you intend to exchange the selected profile information.

4. AI-assisted interest normalization

If you type an interest that is not already in Zync's local catalog and use the AI-assisted add-interest feature, Zync sends the text you entered and your supported language to the Zync API. The server bounds the interest text before processing and asks an AI service to turn it into a stable concept and display label.

This request is processed through Vercel, which hosts the Zync API, and OpenRouter, which routes the request to a compatible AI model provider. Zync's OpenRouter requests require Zero Data Retention-compatible routing and set provider data collection to deny. If no compatible route is available, Zync is designed to fail the AI request rather than intentionally relax those privacy constraints.

The interest text still leaves your device when you invoke this feature. Zync application code does not intentionally add the request text to a cloud user profile or application database.

5. AI-assisted conversation questions

After two profiles are compared, Zync may send a bounded set of relevant interest labels, the selected conversation mode, supported language information, and a random session context value to the Zync API to generate a conversation question. For bilingual use, a secondary language may also be included.

The request does not need your nickname, peer local identifier, QR body, phone number, email address, precise location, or login token. These requests use the same Vercel/OpenRouter processing path and privacy-routing constraints described above. If AI generation fails, Zync can fall back to built-in local questions.

6. Product analytics in the public V1 build

Product analytics are disabled by default in the public V1 build. The release build does not enable Zync's optional analytics transport, so it does not create an analytics installation identifier or send product-analytics events merely because the production API is configured.

Zync contains privacy-filtered analytics code that may be enabled in a future release. If analytics is enabled later, this policy and the Google Play Data safety declaration must be updated before that release is published.

7. Service providers

For the public V1 release, Zync's online features use:

  • Vercel — hosting and execution of the Zync API and encrypted-relay endpoint;
  • Upstash Redis — short-lived storage of the encrypted pairing response and relay state; and
  • OpenRouter — routing optional AI requests to compatible model providers under Zync's request constraints.

The exact underlying AI model provider may vary because Zync can use OpenRouter's free-model router. Provider availability can change over time.

8. Security

The production Android build is designed to communicate with Zync's online API over HTTPS. Pairing responses sent through the temporary relay are additionally encrypted and authenticated on-device with AES-GCM using a one-time 256-bit secret carried in the QR and not sent to the relay endpoint as part of session creation. The server stores only the opaque encrypted response for the short relay lifetime.

Zync applies input and payload-size limits, protocol/version checks, short expiries, one-response semantics, and rate limiting to the relay. For abuse protection, the relay can derive a short-lived HMAC-based rate-limit key from network request information such as the request IP; Zync's application-level rate-limit store does not need to keep the raw IP in that key. Hosting and networking providers may still process network identifiers such as IP addresses under their own applicable terms and security practices.

Zync keeps provider credentials such as the Upstash and OpenRouter server tokens on the server rather than in the Android application. No transmission or storage system can be guaranteed to be completely secure.

9. Retention and deletion

Local data: profile and history information remains on your device until you change it, clear app storage, or uninstall the app, subject to device/OS backup behaviour.

Encrypted pairing relay: the relay stores a random session identifier and either pending state or an opaque encrypted response. A successful host requests deletion immediately after authenticated decryption. If the flow is abandoned or deletion cannot complete, the relay key is configured to expire automatically after about three minutes. Short-lived abuse-protection counters are configured with their own brief expiry. Zync does not use the relay as a permanent profile database.

AI requests: Zync's application code does not intentionally persist AI prompt content to a Zync user-account database, because V1 has no user accounts. OpenRouter requests require Zero Data Retention-compatible routing and deny provider data collection. Hosting, networking, security, relay, and AI providers may still process limited technical metadata under their applicable service terms and security practices.

Because Zync V1 has no account, there is no cloud account dashboard to delete. If you have a privacy inquiry concerning server/provider records, use the privacy contact mechanism below.

10. Children and age information

Zync V1 does not ask users to provide a date of birth or age as part of the app profile. The app should be used consistently with the target-audience settings shown on its Google Play listing and any applicable parental or guardian requirements.

11. Changes to this policy

This policy may be updated when Zync's features, providers, or data practices change. The latest version will remain available at https://zync-inky.vercel.app/privacy with its effective date.
