## Goal

Advance Zync from source-level iOS compile readiness to a reproducible,
fail-closed **signed App Store Connect archive/export path** without uploading
anything to App Store Connect.

This work deliberately does **not** claim that a signed IPA has already been
built. The current repository/account state does not contain the required Google
iOS OAuth client or Apple signing material.

No GitHub Actions macOS runner, App Store Connect upload, Vercel deployment,
Google Play action or production deployment was used.

## New manual signed-archive workflow

Added:

`.github/workflows/zync-ios-signed-archive.yml`

The workflow is `workflow_dispatch` only and requires the operator to type:

`BUILD_SIGNED_IPA`

before consuming a macOS runner.

It has no push/pull_request trigger.

It builds an artifact only. It contains **no App Store upload command/API path**.

## App Store provisioning-profile validator

Added:

`mobile/tool/ios_provisioning_profile.py`

The workflow first decodes the profile CMS envelope using macOS `security cms`,
then this source-controlled helper verifies the decoded plist.

It requires:

- exactly one valid 10-character TeamIdentifier
- valid profile UUID
- iOS platform
- non-expired profile
- exact
  `application-identifier = TEAM_ID.com.gmail.gentle3f.myproject`
- matching `com.apple.developer.team-identifier`
- `get-task-allow = false`
- Sign in with Apple `Default` entitlement
- no `ProvisionedDevices`
- no enterprise `ProvisionsAllDevices=true`

Therefore development, Ad Hoc and enterprise profiles are rejected instead of
being silently accepted for an App Store archive.

The helper can export already-validated:

- team_id
- profile_uuid
- profile_name
- expiration

through GitHub step outputs.

A local fixture with a profile name containing spaces successfully exercised
that output path.

## Deterministic Xcode manual signing

Added:

`mobile/tool/configure_ios_signing.py`

Against a fresh wrapper generated by the current Flutter toolchain, it patches
all three Runner build configurations with:

- `CODE_SIGN_STYLE = Manual`
- validated Apple Team ID
- `Apple Distribution` code-sign identity
- validated provisioning-profile UUID
- validated provisioning-profile specifier/name

It intentionally does not patch RunnerTests.

The helper is idempotent and fails if conflicting target-level manual signing is
already present.

It also generates deterministic `ExportOptions.plist`:

- method: `app-store-connect`
- destination: `export`
- signingStyle: `manual`
- signingCertificate: `Apple Distribution`
- exact team ID
- exact bundle/profile mapping
- `manageAppVersionAndBuildNumber = false`
- `stripSwiftSymbols = true`

The `manageAppVersionAndBuildNumber=false` gate is important: Xcode export is
not allowed to silently rewrite the explicit Zync release version/build number.

## Temporary signing material lifecycle

The signed-archive workflow never stores the P12/profile in the repository.

At run time it:

1. decodes the validated profile/P12 into `RUNNER_TEMP`
2. creates a temporary macOS keychain with a random password
3. imports only the supplied P12
4. requires an `Apple Distribution` codesigning identity to be visible
5. saves and temporarily prepends the runner's original keychain search list
6. installs the validated profile under its UUID
7. builds/exports the IPA
8. on **every exit path**:
   - restores the original keychain search list
   - removes the installed provisioning profile
   - removes temporary P12/profile/entitlements files
   - deletes the temporary keychain

The base64 decoding is performed by Python's standard library rather than
depending on GNU-vs-BSD `base64` flags.

## Signed IPA verification

Added:

`.github/scripts/verify_signed_ipa.py`

This helper verifies IPA artifact provenance **after** macOS cryptographic
`codesign --verify` has already passed.

The workflow performs:

`codesign --verify --deep --strict --verbose=2 <Runner.app>`

It then extracts the signed entitlements and requires:

- Sign in with Apple `Default`
- signed `com.apple.developer.team-identifier` equals validated profile team
- signed `application-identifier = TEAM_ID.bundle_id`

It also decodes and re-validates the **embedded** provisioning profile and
requires the embedded UUID to equal the originally validated profile UUID.

The provenance verifier independently checks:

- IPA is a valid zip with exactly one `Payload/*.app/Info.plist`
- bundle ID
- version name
- build number
- Team ID
- provisioning-profile UUID
- IPA SHA-256
- GitHub archive run ID
- source commit SHA

The helper explicitly does not replace `codesign`; cryptographic signature
verification and provenance verification remain separate gates.

## Artifact handoff

A successful deliberate signed-archive run will upload:

- `Zync-iOS-signed.ipa`
- `Zync-iOS-signed.sha256.txt`
- `Zync-iOS-signed-build.txt`
- `Zync-iOS-dSYMs.zip`
- `Zync-iOS-dSYMs.sha256.txt`

Keeping dSYMs in the same archive handoff closes the future crash-symbolication
gap rather than producing an IPA with no matching debug symbols.

Artifact retention is 14 days.
